# demo-community

HubForge project for the Gainsight CC Widget Catalog.

## Prerequisites

- Node.js >= 18
- [@gainsight-hub/hubforge](https://www.npmjs.com/package/@gainsight-hub/hubforge) installed globally:

```sh
npm install -g @gainsight-hub/hubforge
```

## Widgets (primary)

Widgets are the main artifact this project produces — each renders in its own container on a community page.

```sh
hf create                     # scaffold a widget (interactive)
hf preview                    # start a dev server and pair with CC Widget Catalog
hf list                       # list all discovered widgets
hf connector test <name>      # smoke-test a widget's connector against your tenant
```

## Sitewide scripts & stylesheets (optional)

Scripts and stylesheets are injected on every rendered page (or scoped via `rules`) — for analytics, shared utilities, custom fonts, theming. They are optional; a project with only widgets is valid.

`hf script new` / `hf style new` create a local file (`script.js` / `style.css`) and add the entry to `extensions_registry.json` in one step. `hf script link` / `hf style link` add an external CDN entry without creating any file. All metadata (`placement`, `attributes`, `rules`) lives on the registry entry itself.

```sh
hf script new <name> [--placement bodyEnd] [--attr key=value]
hf script link <url> [--name <slug>] [flags above]
hf style  new <name> [--attr key=value]
hf style  link <url> [--name <slug>] [flags above]
```

## Building & CI

```sh
hf build                      # rebuild every widget + regenerate the registries
hf build --no-widgets         # skip the per-widget build; only regenerate the registries
hf build --validate           # verify registries are in sync with source (used in CI)
```

**Before you commit widget source changes, run `hf build`** at the project root. It rebuilds every widget's `dist/` and refreshes the registries. CI validates that source and `dist/` stay in sync — commits with stale `dist/` fail.

## Layout

```
demo-community/
├── AGENTS.md                     # AI agent working rules (defer to developer-portal.gainsight.com/docs)
├── hubforge.json                 # HubForge project metadata AND project-root marker for the `hf` CLI
├── extensions_registry.json      # committed source of truth (widgets/connectors regenerated by `hf build`; scripts/styles managed via `hf script`/`hf style`)
├── connectors_registry.json      # committed source of truth (regenerated by `hf build` from per-widget connectors.json)
├── widgets/<name>/               # per-widget sources (widget.json + optional connectors.json)
├── scripts/<name>/               # optional sitewide JS scripts (local script.js file only; metadata lives in the registry)
└── stylesheets/<name>/           # optional sitewide CSS stylesheets (local style.css file only; metadata lives in the registry)
```

`hubforge.json` marks the project root - run `hf` commands from inside this directory or a subdirectory (e.g. `widgets/<name>/`); the CLI walks up from your current directory to find it.
